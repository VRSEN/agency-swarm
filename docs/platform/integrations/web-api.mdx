## Feature Overview

API Integrations provide a set of endpoints allowing you to run your agents on custom backends or on other unsupported channels.

API v2 also supports server-controlled, per-member AI allowances for applications built on top of an API Integration. Agencii owns the limit and usage ledger. Your application registers a stable member, checks their current allowance, and sends the returned `consumerId` with each v2 completion.

For a simple explanation and course-platform example, see [Members allowance](/platform/integrations/member-allowances).

## Authentication

- **Note**: You can only use platform tokens for these endpoints. Find or create one inside **Profile Icon > API Keys**.
- **Headers**:
    - `Authorization`: `Bearer <your_token>`
        - **Example**: `Bearer sk-agencii-H7sb111...`
    - `Content-Type`: `application/json`

## Member allowance flow

<Steps>
  <Step title="Configure the policy in Agencii">
    Open the API Integration's **Members allowance** tab, enable limits, and set the default USD allowance. Each member renews monthly on the date they first registered. Client applications cannot set or increase the limit.
  </Step>
  <Step title="Register each application member">
    Call `POST /register_api_consumer` with your stable external user ID. Registration is idempotent, so retries return the same `consumerId`.
  </Step>
  <Step title="Store and reuse consumerId">
    Save the returned `consumerId` on your own user record. Use `POST /get_api_consumer_allowance` to show the current period in your UI.
  </Step>
  <Step title="Attribute every v2 run">
    Send `consumerId` and a unique `usageRequestId` with `POST /get_completion_v2`. When the member has reached the limit, the API returns HTTP `429` before creating a chat turn or starting an agent run.
  </Step>
</Steps>

<Note>
The response already in progress is allowed to finish, so final spend can be slightly above the limit. The next request is blocked. The allowance currently includes AI model usage from the Responses API; file storage, uploads, and sandbox compute are excluded.
</Note>

## Additional Notes

- All timestamps are in ISO 8601 format.
- Ensure that your `apiIntegrationId` is valid and corresponds to an existing integration.
- Replace placeholder values with actual data when making requests.
- The `attachments` parameter in `/get_response` allows you to include files and specify tools for processing.
- API v1 behavior is unchanged and does not enforce per-consumer allowances.
