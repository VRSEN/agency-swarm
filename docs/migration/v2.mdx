Agency Swarm 2.0 runs on new major versions of its core libraries: the OpenAI Python SDK 3, MCP 2 and FastMCP 4, with the OpenAI Agents SDK at 0.26.0. It also changes the default model and compacts long conversations. Most agencies only need a new install. Go through the sections below and change the ones that match your code.

```bash
pip install --pre "agency-swarm==2.0.0b1"
```

2.0.0b1 is a pre-release, so `pip install --upgrade agency-swarm` still installs 1.11. Pass `--pre` and the version, as shown above.

## 1. Raise your dependency pins

If your project pins any of these packages, raise the pins to these ranges:

| Package | Agency Swarm 2.0 needs |
|---|---|
| `openai` | `>=3,<4` |
| `mcp` | `>=2,<3` |
| `fastmcp` | `>=4.0.5,<5` |
| `fastapi` | `>=0.141` |
| `httpx2` | `>=2.13,<3` (replaces `httpx`) |

Agency Swarm pins the OpenAI Agents SDK (`openai-agents`) to one exact version. Do not pin a different one in your project. If your code calls the OpenAI or MCP SDKs directly, read their own migration notes too.

## 2. Install LiteLLM as an extra

LiteLLM is no longer installed by default. Without it, `from agency_swarm import LitellmModel` raises an `ImportError` that explains the fix.

LiteLLM 1.108.0 and newer support `openai` 3 directly, so install the extra with either tool:

<Tabs>
<Tab title="uv">
```bash
uv add "agency-swarm[litellm]"
```
</Tab>
<Tab title="pip">
```bash
pip install "agency-swarm[litellm]"
```
</Tab>
</Tabs>

See [Third-Party Models](/additional-features/third-party-models) for provider setup.

## 3. Add packages your own code imports

Agency Swarm no longer installs `requests`, `types-requests`, `termcolor`, `griffe` or `httpx` for you. If your code imports one of them, add it to your own dependencies.

## 4. Check agents that use the default model

The default model is now `gpt-6-luna` with reasoning effort `medium` and verbosity `low`. Before, it was `gpt-5.6-luna` with effort `none`. Agents without a `model` may answer differently, cost more and take longer.

`gpt-6-luna` rejects `temperature` and `top_p`. An agent that sets them without a model now gets an error from the API. To keep the old behavior, set the model and settings yourself:

```python
from agency_swarm import Agent, ModelSettings
from openai.types.shared import Reasoning

agent = Agent(
    name="Assistant",
    model="gpt-5.6-luna",
    model_settings=ModelSettings(reasoning=Reasoning(effort="none")),
)
```

## 5. Know that long conversations are compacted

For model names that start with `gpt-`, or with `o` and a digit, Agency Swarm now asks the OpenAI API to compact long conversations. Compaction starts at 90% of the model's context window when the Agents SDK knows it, otherwise at 240,000 tokens. Saved history is replayed from the latest compaction, so later turns send fewer tokens. When every agent in the agency runs on an OpenAI model, the `/compact` command in the terminal demo now uses OpenAI's compaction endpoint too.

**To turn compaction off** for an agent, for example on an endpoint that serves a `gpt-*` name but rejects the setting:

```python
ModelSettings(context_management=[])
```

**Set `context_management` on `ModelSettings`, not in `extra_args`:**

<CodeGroup>
```python Before
ModelSettings(extra_args={"context_management": [{"type": "compaction", "compact_threshold": 200_000}]})
```

```python After
ModelSettings(context_management=[{"type": "compaction", "compact_threshold": 200_000}])
```
</CodeGroup>

On an `Agent`, the old `extra_args` form still works: Agency Swarm then skips its own default. On a `RunConfig(model_settings=...)` passed to `get_response()` it does not. The request would carry the setting twice, so every run fails with `responses.create() got multiple values for keyword argument 'context_management'`.

**Your stored history can start at the latest compaction.** Each conversation (the user thread, and each pair of agents that talk to each other) is replayed from its own latest `compaction` item. Items of that conversation stored before it are never sent to the model again. So the `chat_history` you send to `run_fastapi`, and the messages your `load_threads_callback` returns, can drop them. Keep items marked `"message_origin": "compaction_retained"` right before the compaction item: they belong to it.

## 6. Import `Runner` from `agency_swarm`

Agency Swarm no longer patches the Agents SDK. `agents.Runner` now behaves like the stock SDK, so it does not apply your agents' `system_reminders`. Use `agency_swarm.Runner` instead. To save and restore a run, use `run_state_to_json` and `run_state_from_json` from `agency_swarm`.

```python
from agency_swarm import Runner, run_state_from_json, run_state_to_json
```

## 7. Return `AuthorizationCodeResult` from custom OAuth callbacks and registries

MCP 2 rejects an OAuth callback without `iss` when the authorization server says it supports one, so callbacks must now pass `iss` through in an `AuthorizationCodeResult` instead of returning a `(code, state)` tuple. The default local handler and the built-in in-memory registry in `run_fastapi()` already do this for you.

**If you pass a custom `callback_handler` to `MCPServerOAuth`**, return an `AuthorizationCodeResult`:

<CodeGroup>
```python Before
async def wait_for_code() -> tuple[str, str | None]:
    return await poll_frontend()
```

```python After
from mcp.shared.auth import AuthorizationCodeResult

async def wait_for_code() -> AuthorizationCodeResult:
    code, state, iss = await poll_frontend()
    return AuthorizationCodeResult(code=code, state=state, iss=iss)
```
</CodeGroup>

**If you pass a custom `oauth_registry` to `run_fastapi()`** (for example in a multi-worker deployment), update both `set_code()` and `wait_for_code()`. `run_fastapi()` now calls `set_code()` with `iss=iss`, and expects `wait_for_code()` to return an `AuthorizationCodeResult`:

<CodeGroup>
```python Before
async def set_code(
    self,
    *,
    state: str,
    code: str,
    user_id: str | None,
) -> OAuthFlowState:
    ...

async def wait_for_code(
    self,
    *,
    state: str,
    timeout: float | None = 300.0,
) -> tuple[str, str | None]:
    return flow.code, flow.state
```

```python After
from mcp.shared.auth import AuthorizationCodeResult

async def set_code(
    self,
    *,
    state: str,
    code: str,
    user_id: str | None,
    iss: str | None = None,
) -> OAuthFlowState:
    ...  # store iss alongside code

async def wait_for_code(
    self,
    *,
    state: str,
    timeout: float | None = 300.0,
) -> AuthorizationCodeResult:
    return AuthorizationCodeResult(
        code=flow.code,
        state=flow.state,
        iss=flow.iss,
    )
```
</CodeGroup>

## 8. Pass a host to reach the browser demos from another machine

`agency.copilot_demo()` and `RealtimeDemoLauncher.start()` now listen on `127.0.0.1`, so only your own machine can open them. Pass `host="0.0.0.0"` when you run them in Docker or on a remote server.

`run_fastapi()`, `agency.run_fastapi()`, and `run_mcp()` still listen on `0.0.0.0` (over HTTP and SSE for `run_mcp()`). When they do and `APP_TOKEN` is not set, they now log a warning that anyone who can reach the port can call them.

`run_realtime()` also still listens on `0.0.0.0`, but it has no token check and logs no token warning. Anyone who can reach the port can connect unless you put authentication in front of it or pass `host="127.0.0.1"`.

## 9. Turn OpenAI traces back on if you use a custom endpoint

When `OPENAI_BASE_URL` points anywhere other than `api.openai.com`, Agency Swarm no longer lets the Agents SDK upload traces to OpenAI. The SDK sent them with `OPENAI_API_KEY`, which is your endpoint's key. Langfuse, AgentOps and your own trace processors still get every trace.

If you read these traces in the OpenAI dashboard, set `OPENAI_AGENTS_DISABLE_TRACING=0` and give the exporter an OpenAI key:

```python
from agents import set_tracing_export_api_key

set_tracing_export_api_key("sk-...")
```

See [Observability](/additional-features/observability#custom-model-endpoints) for the setups this does not cover.

## 10. Replace deprecated APIs

`Agency(user_context=...)` and `agency.user_context` are deprecated. They still work but emit a `DeprecationWarning`. Pass state per run with `context_override`, as shown in [Agency Context](/additional-features/agency-context).

## 11. Check OpenAI Agents SDK 0.26.0 changes

Agency Swarm 2.0 moves the pinned OpenAI Agents SDK from `0.22.3` to `0.26.0`. Check the points below if your code calls these SDK APIs directly.

**Import `function_tool` from `agency_swarm` to keep detailed tool errors.** Starting in SDK 0.23, `agents.function_tool` hides Python exception text from the model and returns `"An error occurred while running the tool."`. Agency Swarm's `@agency_swarm.function_tool`, `BaseTool`, and `ToolFactory.from_mcp()` still return the exception message so models can fix bad inputs and retry. If you imported `from agents import function_tool`, switch the import to `from agency_swarm import function_tool`, pass a custom `failure_error_function`, or set `RunConfig(tool_error_formatter=...)`.

**Handle `"tool_exception"` in custom `tool_error_formatter` callbacks.** SDK 0.24 added `kind="tool_exception"` (with an optional `error` field) to `ToolErrorFormatterArgs`, and Agency Swarm tools now honor `RunConfig.tool_error_formatter`. If your formatter assumes every non-rejection is a missing tool, handle `"tool_exception"` explicitly or return `None` to keep the default error message.

**Finish old `RunState` checkpoints and use unique agent names.** SDK 0.24 moved `RunState` serialization to schema `1.21` and SDK 0.25 moved it to schema `1.22`. Saved graphs where two non-root agents share a name and differ only by hook instance attributes are now rejected instead of risking wrong agent assignment, and Pydantic run contexts keep defaults and in-place edits. Finish in-flight tasks saved on older SDKs before upgrading, give every agent a unique name in new durable runs, and upgrade checkpoint readers before writers because older SDKs cannot read schema `1.21` or `1.22`.

**Replace removed or changed SDK sandbox, Realtime tracing, and Codex options.** If you use these Agents SDK features directly:

- **Docker sandbox mounts:** SDK 0.26 rejects `InContainerMountStrategy` (including read-only mounts), privileged containers, and containers with added capabilities. Switch to `DockerVolumeMountStrategy` (or mount on the Docker host with a trusted `SandboxPathGrant`) and start a fresh sandbox session. SDK 0.25 also removed the beta Runloop sandbox provider; migrate those workloads to another supported sandbox provider such as Modal.
- **Custom `TraceProvider` with Realtime:** SDK 0.26 makes Realtime check `TraceProvider.is_disabled()`, which defaults to `True` on custom subclasses. Override `is_disabled()` to return the same state tracked by `set_disabled()` so server traces stay on (the built-in provider already does this).
- **Local images in the experimental Codex tool:** SDK 0.26 no longer allows a model-supplied file path to open a local image. Pass named grants with `image_attachments={"diagram": "/abs/path/to/diagram.png"}` and reference `"diagram"` as the `local_image` path.
- **Direct `OpenAIResponsesCompactionSession` usage:** SDK 0.25 changed the default compaction model from `gpt-4.1` to `gpt-6-luna`. Pass `model="gpt-4.1"` if you construct `OpenAIResponsesCompactionSession` directly and want the earlier default.
