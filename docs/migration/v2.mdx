Most agencies need only a new install to move from 1.11 to 2.0. Install it first. Then use the table to find the steps that match your code.

## Install

```bash
pip install --pre "agency-swarm==2.0.0b1"
```

<Note>
2.0.0b1 is a pre-release, so `pip install --upgrade agency-swarm` still installs 1.11. Pass `--pre` and the version, as shown above.
</Note>

## Find your steps

| If your code... | Go to |
|---|---|
| Creates an agent without a `model` | [Default model](#default-model) |
| Runs long conversations on OpenAI models, or stores chat history | [Conversation compaction](#conversation-compaction) |
| Pins `openai`, `mcp`, `fastmcp`, `fastapi` or `httpx` | [Dependencies](#dependencies) |

If no row matches your code, the new install is all you need.

## Default model

The default model is now `gpt-6-luna` with reasoning effort `medium` and verbosity `low`. Before, it was `gpt-5.6-luna` with reasoning effort `none`. An agent without a `model` may now answer differently, cost more and take longer.

To keep the old behavior, set the model and the reasoning effort yourself:

```python
from agency_swarm import Agent, ModelSettings
from openai.types.shared import Reasoning

agent = Agent(
    name="Assistant",
    model="gpt-5.6-luna",
    model_settings=ModelSettings(
        reasoning=Reasoning(effort="none"),
    ),
)
```

<Warning>
`gpt-6-luna` rejects `temperature` and `top_p`. An agent that sets either one and has no `model` now gets an error from the API. Set a `model` on that agent, as in the example above, or remove the two settings.
</Warning>

## Conversation compaction

Agency Swarm now asks the OpenAI API to compact long conversations. The API adds a `compaction` item that stands for everything before it. Saved history is replayed from the latest `compaction` item, so later turns send fewer tokens.

Compaction is on for model names that start with `gpt-`, or with `o` and a digit, such as `o3`. Most agencies need no change. Open the case that matches yours:

<AccordionGroup>
<Accordion title="You want to turn compaction off">
Do this when your endpoint serves a `gpt-*` model name but rejects the setting. Turn compaction off on the agent:

```python
from agency_swarm import Agent, ModelSettings

agent = Agent(
    name="Assistant",
    model_settings=ModelSettings(
        context_management=[],
    ),
)
```
</Accordion>

<Accordion title="You set context_management in extra_args">
Set `context_management` on `ModelSettings` instead:

<CodeGroup>
```python Before
ModelSettings(
    extra_args={
        "context_management": [
            {"type": "compaction", "compact_threshold": 200_000},
        ],
    },
)
```

```python After
ModelSettings(
    context_management=[
        {"type": "compaction", "compact_threshold": 200_000},
    ],
)
```
</CodeGroup>

On an `Agent`, the old form still works: Agency Swarm then skips its own default.

On a `RunConfig(model_settings=...)` passed to `get_response()`, the old form fails. The request would carry the setting twice, so every run stops with `responses.create() got multiple values for keyword argument 'context_management'`.
</Accordion>

<Accordion title="You store conversation history yourself">
This covers the `chat_history` you send to `run_fastapi` and the messages your `load_threads_callback` returns.

Each conversation is replayed from its own latest `compaction` item. A conversation is the user thread, or one pair of agents that talk to each other. Items of that conversation stored before the `compaction` item are never sent to the model again, so your stored history can leave them out.

Keep the items marked `"message_origin": "compaction_retained"` right before the `compaction` item. They belong to it.
</Accordion>

<Accordion title="When compaction starts, and the /compact command">
Compaction starts at 90% of the model's context window when the Agents SDK knows the window. Otherwise it starts at 240,000 tokens.

The `/compact` command in the terminal demo now uses OpenAI's compaction endpoint too, when every agent in the agency runs on an OpenAI model.
</Accordion>
</AccordionGroup>

## Dependencies

Agency Swarm 2.0 runs on new major versions of its core libraries: the OpenAI Python SDK 3, MCP 2 and FastMCP 4.

### Raise your pins

If your project pins any of these packages, raise the pins to these ranges:

| Package | Agency Swarm 2.0 needs |
|---|---|
| `openai` | `>=3,<4` |
| `mcp` | `>=2,<3` |
| `fastmcp` | `>=4.0.5,<5` |
| `fastapi` | `>=0.141` |
| `httpx2` | `>=2.13,<3` (replaces `httpx`) |

Agency Swarm pins the OpenAI Agents SDK (`openai-agents`) to one exact version, now 0.22.3. Do not pin a different one in your project.

If your code calls the OpenAI or MCP SDKs directly, read their own migration notes too.

### Add packages your own code imports

Agency Swarm no longer installs `requests`, `types-requests`, `termcolor`, `griffe` or `httpx` for you. If your code imports one of them, add it to your own dependencies.

## LiteLLM

LiteLLM is no longer installed by default. Without it, `from agency_swarm import LitellmModel` raises an `ImportError`. Install the `litellm` extra:

<Tabs>
<Tab title="pip">
```bash
pip install "agency-swarm[litellm]"
```
</Tab>
<Tab title="uv">
```bash
uv add "agency-swarm[litellm]"
```
</Tab>
</Tabs>

If you pin LiteLLM yourself, use 1.108.0 or later. LiteLLM 1.108.0 and later accept `openai` 3.

See [Third-Party Models](/additional-features/third-party-models) for provider setup.

## Runner

Import `Runner` from `agency_swarm`:

<CodeGroup>
```python Before
from agents import Runner
```

```python After
from agency_swarm import Runner
```
</CodeGroup>

Agency Swarm no longer patches the Agents SDK. `agents.Runner` now behaves like the stock SDK, so it does not apply your agents' `system_reminders`. `agency_swarm.Runner` does.

To save and restore a run, use `run_state_to_json` and `run_state_from_json` from `agency_swarm`:

```python
from agency_swarm import (
    Runner,
    run_state_from_json,
    run_state_to_json,
)
```

## OAuth callbacks

An OAuth callback now returns an `AuthorizationCodeResult` instead of a `(code, state)` tuple. The new object also carries `iss`, the issuer value that the authorization server sends back. MCP 2 rejects a callback without `iss` when the authorization server says it supports one.

The default local handler and the built-in in-memory registry of `run_fastapi()` already do this for you. Open the case that matches yours:

<AccordionGroup>
<Accordion title="You pass a custom callback_handler to MCPServerOAuth">
Return an `AuthorizationCodeResult`:

<CodeGroup>
```python Before
async def wait_for_code() -> tuple[str, str | None]:
    return await poll_frontend()
```

```python After
from mcp.shared.auth import AuthorizationCodeResult

async def wait_for_code() -> AuthorizationCodeResult:
    code, state, iss = await poll_frontend()
    return AuthorizationCodeResult(code=code, state=state, iss=iss)
```
</CodeGroup>
</Accordion>

<Accordion title="You pass a custom oauth_registry to run_fastapi()">
You may have one in a deployment with several workers. Update both `set_code()` and `wait_for_code()`. `run_fastapi()` now calls `set_code()` with `iss=iss`, and expects `wait_for_code()` to return an `AuthorizationCodeResult`:

<CodeGroup>
```python Before
async def set_code(
    self,
    *,
    state: str,
    code: str,
    user_id: str | None,
) -> OAuthFlowState:
    ...

async def wait_for_code(
    self,
    *,
    state: str,
    timeout: float | None = 300.0,
) -> tuple[str, str | None]:
    return flow.code, flow.state
```

```python After
from mcp.shared.auth import AuthorizationCodeResult

async def set_code(
    self,
    *,
    state: str,
    code: str,
    user_id: str | None,
    iss: str | None = None,
) -> OAuthFlowState:
    ...  # store iss alongside code

async def wait_for_code(
    self,
    *,
    state: str,
    timeout: float | None = 300.0,
) -> AuthorizationCodeResult:
    return AuthorizationCodeResult(
        code=flow.code,
        state=flow.state,
        iss=flow.iss,
    )
```
</CodeGroup>
</Accordion>
</AccordionGroup>

## Server and demo hosts

The browser demos now listen only on your own machine. The servers still listen on every network interface.

- `agency.copilot_demo()` and `RealtimeDemoLauncher.start()` now listen on `127.0.0.1`, so only your own machine can open them. Pass `host="0.0.0.0"` when you run them in Docker or on a remote server.
- `run_fastapi()`, `agency.run_fastapi()` and `run_mcp()` still listen on `0.0.0.0`. For `run_mcp()`, that means the HTTP and SSE transports. When `APP_TOKEN` is not set, they now log a warning that anyone who can reach the port can call them.
- `run_realtime()` also still listens on `0.0.0.0`, but it has no token check and logs no token warning. Anyone who can reach the port can connect, unless you put authentication in front of it or pass `host="127.0.0.1"`.

## OpenAI traces

When `OPENAI_BASE_URL` points anywhere other than `api.openai.com`, Agency Swarm no longer lets the Agents SDK upload traces to OpenAI. The SDK sent them with `OPENAI_API_KEY`, which is your endpoint's key. Langfuse, AgentOps and your own trace processors still get every trace.

If you read these traces in the OpenAI dashboard, turn the upload back on. Set `OPENAI_AGENTS_DISABLE_TRACING=0` and give the exporter an OpenAI key:

```python
from agents import set_tracing_export_api_key

set_tracing_export_api_key("sk-...")
```

See [Observability](/additional-features/observability#custom-model-endpoints) for the setups this does not cover.

## Deprecated APIs

`Agency(user_context=...)` and `agency.user_context` still work, but they emit a `DeprecationWarning`. Pass state on each run with `context_override`:

<CodeGroup>
```python Before
agency = Agency(agent, user_context={"plan": "pro"})
response = await agency.get_response("Hello")
```

```python After
agency = Agency(agent)
response = await agency.get_response(
    "Hello",
    context_override={"plan": "pro"},
)
```
</CodeGroup>

See [Agency Context](/additional-features/agency-context) to carry state from one run to the next.
